# China Job Market Pulse 产品需求文档

## 1. 产品概述

**China Job Market Pulse** 是一个面向中国技术岗位市场的开源分析工具。它把用户拥有权限的职位数据、公开发布的数据集或用户导出的 CSV/JSON 文件，转换为可复现的薪资、技能、城市、经验、学历和时间趋势报告。

项目的核心不是提供某个招聘网站的“实时镜像”，而是提供一个数据来源无关、可审计、可复现的分析层：使用者可以知道数据来自哪里、何时采集、经过了哪些清洗，以及报告中的数字如何由输入数据计算得到。

## 2. 目标用户

- **求职者**：了解目标岗位的薪资区间、技能需求和城市分布。
- **职业与招聘研究者**：对职位样本进行结构化统计，观察岗位要求变化。
- **招聘与 HR 从业者**：快速查看岗位供需信号和技能热度，不替代正式薪酬调研。
- **开源贡献者**：新增数据适配器、分析指标、可视化组件和质量规则。

## 3. 要解决的问题

用户通常需要回答以下问题：

1. 某类岗位的月薪范围、均值、中位数和样本量是多少？
2. 哪些城市的岗位最多，城市之间是否存在明显差异？
3. 哪些技能出现频率最高，技能组合是否随岗位类别变化？
4. 经验和学历要求如何分布？
5. 在给定的采集时间或发布时间范围内，指标是否发生变化？
6. 结果能否被复跑、导出、检查，并由其他人复核？

## 4. MVP 范围

### 4.1 输入

- CSV 和 JSON 文件。
- 明确记录字段含义、单位和数据来源。
- 支持缺失的薪资、经验、学历和发布时间，并在质量报告中说明缺失情况。
- 允许用户提供自有导出数据或合法公开数据集。

### 4.2 处理

- 字段类型校验和行级错误定位。
- 城市、职位名称、技能文本的基础规范化。
- 技能分隔符兼容中文逗号、顿号、分号和换行。
- 薪资上下限、日期和 URL 的一致性校验。
- 确定性去重，并保留数据来源与处理版本。

### 4.3 分析与输出

- 薪资：样本量、最小值、最大值、均值、中位数和缺失率。
- 城市：数量、占比和可选的薪资对比。
- 技能：出现次数、占比和岗位类别交叉统计。
- 经验与学历：分组计数、占比和薪资摘要。
- 时间：按日、周或月的样本量和核心指标趋势。
- Markdown、JSON 和 CSV 输出；后续增加本地仪表盘。

## 5. 用户故事

- 作为求职者，我可以用一份职位 CSV 生成一份薪资与技能报告。
- 作为研究者，我可以查看每一行数据的校验结果，并复现同一份报告。
- 作为贡献者，我可以根据公开 schema 新增数据源适配器，而不修改分析核心。
- 作为审阅者，我可以从报告追溯到输入文件、数据时间范围和软件版本。

## 6. 明确不在范围内的功能

- 未经授权的登录、绕过验证码、规避访问限制或批量抓取。
- 自动投递简历、自动发送私信或代表用户作出招聘决策。
- 对个人求职者进行画像、评分或推断敏感属性。
- 把样本统计解释为整个劳动力市场的因果结论。
- 收集姓名、手机号、邮箱、账号凭证等不必要的个人信息。
- 在仓库中保存 API key、Cookie、访问令牌或原始私人数据。

## 7. MVP 验收标准

- [ ] 使用仓库内样例数据可以完成一次端到端导入和报告生成。
- [ ] 样例数据至少包含 10 条记录，并能复现文档中给出的关键统计结果。
- [ ] 无效行能显示行号、字段名和可读错误原因。
- [ ] 重复记录的识别结果是确定性的，并且不会静默改变原始数据。
- [ ] JSON 输出包含数据质量摘要、分析结果和运行元数据。
- [ ] Markdown 报告包含输入文件、记录数、时间范围和主要指标。
- [ ] README 中的安装、测试和示例命令可以在干净环境执行。
- [ ] 核心逻辑有自动化测试，且测试命令通过。

## 8. 非功能要求

- **可复现**：同一输入、同一配置和同一版本应产生等价结果。
- **可解释**：每个汇总指标都能定位到字段定义和计算规则。
- **离线优先**：核心分析不依赖在线服务；数据适配器单独管理网络访问。
- **隐私优先**：默认只处理职位级字段，不接收不必要的个人信息。
- **可扩展**：数据源、分析指标和输出格式通过模块边界扩展。
- **稳定性**：输入异常应转化为质量错误或警告，不应产生难以解释的静默结果。

## 9. 版本策略

- `v0.1.x`：当前 CLI 原型，支持样例数据、基础统计和 Markdown/JSON 输出。
- `v0.2.x`：规范化数据模型、质量报告、去重、趋势分析和更稳定的 JSON schema。
- `v0.3.x`：本地可视化仪表盘和数据导入向导。
- `v1.0.x`：稳定 CLI/API、完整文档、版本化 schema 和发布流程。

每个里程碑都必须经过测试、文档更新、变更记录和独立 Git 提交。

## 10. 当前决策

本阶段只锁定产品边界和验收口径，不提前承诺任何特定招聘网站的接口可用性。下一阶段将把本需求转化为工程规范、贡献流程和可执行的质量门禁。
