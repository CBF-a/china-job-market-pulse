# 开发路线图

## 里程碑总览

| 里程碑 | 目标 | 状态 |
| --- | --- | --- |
| M0 | 产品边界、数据契约和 MVP 验收标准 | 已完成 |
| M1 | 工程规范、贡献流程和质量门禁 | 待开始 |
| M2 | 数据模型、校验、清洗、去重和版本化数据集 | 已完成 |
| M3 | 薪资、技能、城市、经验、学历和时间趋势分析 | 已完成 |
| M4 | CLI、JSON/CSV/Markdown 输出和可复现报告 | 已完成 |
| M5 | 本地可视化仪表盘和演示体验 | 已完成 |
| M6 | 合规数据导入适配器和数据质量监控 | 已完成 |
| M7 | 测试、类型检查、CI、打包和发布 | 待开始 |
| M8 | 公开演示、反馈闭环和 OpenAI OSS 申请材料 | 待开始 |

## M0：产品与数据边界

### 交付物

- `docs/PRD.md`
- `docs/DATA_SCHEMA.md`
- `docs/ARCHITECTURE.md`
- `docs/ROADMAP.md`

### 验收标准

- 明确用户、核心问题、MVP 范围和非目标。
- 明确字段、单位、错误/警告规则和隐私边界。
- 明确从输入到报告的模块边界。
- 后续开发可以根据文档写出可执行测试，而不是依赖口头约定。

## M1：工程基础

### 计划工作

- 整理 README 的快速开始、目录说明和开发命令。
- 增加贡献指南、行为规范和问题模板。
- 固定格式化、测试、类型检查和构建命令。
- 建立变更日志和版本发布规则。

### 退出条件

- 新贡献者可以在干净环境安装、测试并运行样例。
- CI 能在拉取请求中执行核心质量检查。

## M2：数据层

### 已完成

- 将当前 CSV/JSON 字段映射到规范化数据模型。
- 增加行级质量错误、警告和统计摘要。
- 实现稳定的文本、城市、学历、薪资和日期规范化。
- 实现确定性去重和 `record_id` provenance 元数据。
- 增加 fixture，覆盖缺失值、异常值、重复值、JSON 输入和中文分隔符。

### 退出条件（已满足）

- 无效输入可定位到具体行和字段。
- 处理前后记录数和丢弃原因可解释。
- 同一 fixture 多次运行结果一致。

## M3：分析层

### 已完成

- 完善薪资分布、完整区间计数和缺失率统计。
- 增加城市、技能、经验、学历和岗位类别分析。
- 增加按月趋势聚合，并为每个指标提供样本量和占比。
- 固定并测试并列排序、无日期和无薪资边界行为。

### 退出条件（已满足）

- 每个核心指标有单元测试和至少一个边界用例。
- 报告能够区分样本不足、字段缺失和真实的零值。

## M4：报告与 CLI 稳定化

### 已完成

- 固定 CLI 参数、严格质量门禁和退出码。
- 让 Markdown、JSON、CSV 输出共享同一份报告模型。
- 增加 `schema_version`、输入摘要、质量摘要和分析版本。
- 增加端到端 CLI 测试和可复制命令。

### 退出条件（已满足）

- 新用户可以在 10 分钟内从样例数据生成报告。
- 同一输入的 JSON 输出字段和排序稳定。

## M5：本地仪表盘

### 已完成

- 提供 `jobpulse dashboard` 本地生成命令和样例数据预览。
- 展示薪资、城市、技能、经验、学历、岗位类别和时间趋势。
- 支持城市筛选，并在仪表盘中显示数据质量摘要。
- 输出为不依赖外部资源的单个 HTML 文件。

### 退出条件（已满足）

- 仪表盘不依赖在线账号即可使用样例数据。
- 图表数值与 CLI 报告一致。

## M6：合规数据导入与质量监控

### 已完成

- 提供带来源名称、许可和访问方式的本地文件适配器。
- 增加拒绝率、重复率和警告率阈值监控。
- CLI 支持将来源元数据写入报告。
- 明确不实现绕过访问控制或验证码的逻辑。

### 退出条件（已满足）

- 适配器可以在没有核心分析代码变更的情况下单独测试和替换。
- 每次导入生成质量摘要和来源记录。

## M7：发布工程

### 计划工作

- 完善单元测试、集成测试和端到端测试。
- 增加类型检查、构建检查和依赖审计。
- 配置 GitHub Actions、包构建和版本标签。
- 生成发布说明和升级迁移说明。

### 退出条件

- CI 在主分支和拉取请求中通过。
- 可以从发布标签构建并安装包。

## M8：公开演示与 OSS 申请

### 计划工作

- 发布脱敏或合成的可复现实例。
- 整理功能截图、演示视频、使用文档和维护记录。
- 记录用户反馈、已修复问题和后续路线图。
- 根据官方申请要求准备项目简介、许可证、活跃提交和演示链接。

### 退出条件

- 公开仓库内容、许可证和演示链接一致且可访问。
- 申请材料中的每项事实都能由仓库或公开页面验证。

## 交付节奏

每个里程碑遵循同一闭环：

1. 写明目标和验收标准。
2. 小批量实现，避免跨阶段混入功能。
3. 运行测试、静态检查和手工示例。
4. 检查 `git diff` 与敏感信息。
5. 使用独立提交记录里程碑结果。
6. 同步 GitHub 并记录下一阶段入口。
